Политика конфиденциальности — Договор24 Sign

Последнее обновление: 23 ноября 2026 г.

Summary for reviewers (EN). «Договор24 Sign» is a browser extension that performs electronic-signature (GOST/RSA) operations for new.dogovor24.kz and Kazakhstan government services that rely on NCALayer, replacing the NCALayer desktop app. All private keys, the master password, settings, delegation tokens and the local signature log are stored locally in the browser, encrypted (AES-GCM + PBKDF2); a key used for a one-time signature (“Sign with another key (one-time)”) is not stored at all — its file and password are used only for that signature. Biometric unlock uses WebAuthn (Windows Hello / Touch ID): biometric data is handled entirely by the operating system and is never accessible to the extension — only a credential identifier and its public key are stored locally. The developer does not collect, sell or share user data; support requests the user sends voluntarily (feedback form or email) are used only to reply and are deleted on request. Certificate details (name, IIN, organization, validity) are given to a website only after the user allows it, once per site, or through auto sign-in and agent tokens the user set up; the list of these sites (and of sites that received a signature, which carries the same certificate) is kept only on the device, shown in Settings, and access can be revoked there. Apart from the optional Dogovor24 features described below (Google Docs → Dogovor24 and new-document notifications), outbound requests go only to the Kazakhstan National Certification Authority: the timestamp authority tsp.pki.gov.kz during signing (hash of the signature only) and, when signing documents for ESEDO (the government e-document exchange) or embedding a signature inside a PDF, the OCSP responder ocsp.pki.gov.kz and, if needed, the CA certificate files on pki.gov.kz / root.gov.kz (the certificate serial number and hashes of the issuing CA — never the document or the key). If the user also has the NCALayer desktop app installed, the extension may hand the page's own signing request over to it on the local address 127.0.0.1:13579 (for example when the user cancels the extension's dialog) — that connection never leaves the user's machine. Google Docs → Dogovor24 (only for users currently signed in to new.dogovor24.kz in the same browser, and only when the user clicks): the extension reads the user's own Dogovor24 session cookies (access_token, workspace_id) locally via the cookies API and uses them solely to call new.dogovor24.kz on the user's behalf — upload the chosen document, list the user's folders, add the user's own signature. The token is never stored by the extension or sent anywhere else. The Google document the user chose to send is exported to PDF from docs.google.com with the user's existing Google session (no OAuth, no access to other files) and uploaded only to Dogovor24. Optional new-document notifications (off by default; the user turns them on in Settings, and Chrome then asks for the optional notifications permission): while the user is signed in to new.dogovor24.kz, the extension checks once a minute, with the same session, the counter and the list of the user’s own incoming Dogovor24 documents awaiting signature, approval or review, and shows a system notification about new ones. Only the title, sender, action and deadline are used and kept locally; documents are not downloaded. Optional Google Drive (off by default; the user clicks “Connect Google Drive” in Settings, and Chrome then asks for the optional identity permission): the user signs in with Google in Google’s own window (chrome.identity.launchWebAuthFlow, scope drive.file — access only to files the extension itself creates); the PDFs the user signs are uploaded to a folder in the user’s own Drive and shared only as the user chooses (anyone with the link, or a specific person whom Google emails). If the user ticks “Convert to PDF” for a Word, Excel, PowerPoint or similar document, the extension uploads it to the user’s Drive for conversion, downloads the resulting PDF and immediately deletes the temporary copy; images are converted on the device. The Google account email is shown in Settings and written into the PDF signature so that the other party can return the signed file. The access token is kept only in browser session memory; “Disconnect” revokes it. The extension’s use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Error log: errors and NCALayer requests from sites (date and time, error text, site address, the shape of the request without documents, keys or passwords) are kept only on the device for 30 days; the developer receives them only if the user copies the report and sends it themselves. No analytics, no tracking, no remote code.

1. Кто мы

«Договор24 Sign» — расширение для браузера Chrome, которое позволяет подписывать документы электронной цифровой подписью (ЭЦП) и входить по ЭЦП на сайте new.dogovor24.kz и на государственных сервисах Казахстана, использующих NCALayer (например egov.kz), прямо в браузере — без установки отдельной программы NCALayer.

2. Какие данные обрабатываются

  • Файлы ключей ЭЦП (.p12/.pfx), которые вы импортируете, и пароль от них.
  • Мастер-пароль расширения (если вы его задаёте) и настройки (блокировка, подтверждение подписи и т. п.).
  • Данные биометрической разблокировки (если вы её включаете): идентификатор WebAuthn-учётных данных и их публичный ключ. Сами биометрические данные (отпечаток, лицо) обрабатываются операционной системой (Windows Hello / Touch ID) и расширению никогда не доступны.
  • Токены доступа для автоматизации (если вы их создаёте): название, выбранный ключ, список сайтов, срок действия и счётчик использований.
  • Локальный журнал подписей: время, сайт-инициатор, имя ключа и способ подтверждения последних операций подписания.
  • Файлы, которые вы подписываете или перетаскиваете в расширение: формат проверяется и подпись формируется только на вашем устройстве; в Договор24 файл уходит, только если вы нажали «Отправить в Договор24», а на Google Диск — если вы подключили Диск и оставили отмеченным «Сохранить копию на Google Диск». Если у документа (Word, Excel, PowerPoint и т. п.) вы отметили «Конвертировать в PDF», он загружается на ваш Google Диск для конвертации (см. раздел 4); изображения конвертируются на вашем устройстве.
  • Если вы подключили Google Диск: адрес вашего аккаунта Google (показывается в Настройках и вписывается в подпись PDF, сохранённого на Диск, — по нему вторая сторона может вернуть вам подписанный файл), название и номер папки на Диске, выбранные настройки доступа; адреса, которые вы сами вводите, чтобы отправить файл следующему подписанту, и адрес отправителя из подписи, когда вы возвращаете ему файл; токен доступа Google — только в памяти браузера.
  • Если вы пользуетесь Договор24 (функция «Google Docs → Договор24»): токен вашей сессии Договор24 (cookie access_token) и номер пространства (workspace_id) — расширение читает их в браузере в момент действия и не сохраняет; email из токена показывается в Настройках; выбранная папка для загрузки и список папок хранятся локально; документ Google, который вы отправляете, обрабатывается только в момент отправки, в виде PDF.
  • Если вы включили уведомления о новых документах: название, отправитель, вид действия (подписать, согласовать, ознакомиться) и срок документов из ваших «Моих входящих» Договор24. Они хранятся локально и показываются в уведомлении и в окне расширения; сами документы не скачиваются.
  • Журнал ошибок хранится только на вашем компьютере 30 дней: дата и время, текст ошибки, адреса сайтов, обращавшихся к NCALayer, и вид их запросов, без документов, ключей и паролей. Разработчик получает его, только если вы сами скопируете отчёт и отправите.
  • Список сайтов, которым видны ФИО и ИИН: адрес сайта, когда вы разрешили доступ, какой ключ выбрали для него, сколько раз и когда сайт последний раз получал данные, а для сайтов, которым вы отправляли подпись (в ней тоже ФИО и ИИН), — число подписей и дата последней. Хранится только на вашем компьютере; отозвать доступ можно в Настройках.
  • Обращения к разработчику: если вы пишете через форму обратной связи или на почту, разработчик получает то, что вы указали сами: текст, отчёт об ошибке и, по желанию, контакт для ответа. Они нужны только чтобы ответить и исправить ошибку, хранятся в Google Формах и почте разработчика и удаляются после ответа или по вашей просьбе.

Эти данные нужны только для подписи на вашем устройстве и для отправки выбранных вами документов в Договор24 или на ваш Google Диск. Кроме обращений, которые вы сами отправили разработчику, они видны только вам.

3. Где хранятся данные

Все ключи, настройки, токены и журнал хранятся только локально в вашем браузере (IndexedDB и chrome.storage). Приватные ключи шифруются алгоритмом AES-GCM с ключом, выведенным через PBKDF2 из вашего мастер-пароля или локального секрета устройства. Токен доступа Google (если вы подключили Google Диск) хранится только в памяти браузера и стирается при его закрытии. Ключ, которым вы подписываете разово («Подписать другим ключом (разово)»), не сохраняется: файл ключа и пароль используются только для этой подписи. Мы (разработчик) не получаем доступ к этим данным и никуда их не передаём.

4. Передача данных третьим лицам

Разработчик не получает ваших данных, кроме обращений, которые вы отправили сами. Данные сертификата (ФИО, ИИН, организация) и подпись расширение передаёт только сайту, на котором вы работаете: после вашего разрешения или по правилам, которые вы включили сами (авто-вход, токены агентов). Сетевые запросы ограничены:

  • сайты, на которых вы подписываете (egov.kz, КГД, goszakup.gov.kz, ИС ЭСФ, stat.gov.kz, enbek.kz, elicense.kz, imei.kz, new.dogovor24.kz и другие порталы с NCALayer) — это сайты, на которых вы и так работаете; расширение лишь обеспечивает подписание и вход на них, подменяя NCALayer. Никакой информации о посещённых сайтах разработчику не передаётся.
  • tsp.pki.gov.kz — государственная служба меток времени (TSA) Республики Казахстан; туда отправляется только хеш подписи для получения метки времени RFC 3161 (требование формата CAdES-T). Сам документ и ключ туда не отправляются.
  • ocsp.pki.gov.kz — служба проверки статуса сертификатов (OCSP) Национального удостоверяющего центра РК; запрос уходит при подписи документов для ЕСЭДО (электронного документооборота госорганов) и при подписи внутри PDF. Туда отправляется серийный номер сертификата и хеши данных удостоверяющего центра, выдавшего его, — чтобы получить подтверждение «сертификат действителен», которое вкладывается в подпись (этого требуют формат ЕСЭДО и долговременная подпись PDF). При подписи внутри PDF так же проверяется сертификат службы меток времени, а недостающие сертификаты удостоверяющих центров скачиваются с сайтов НУЦ (pki.gov.kz, root.gov.kz). Сам документ и ключ туда не отправляются.
  • Google Диск (accounts.google.com, www.googleapis.com) — только если вы сами подключили Google Диск в Настройках. Вход выполняется в окне Google; расширение получает доступ drive.file — только к файлам, которые само создаёт на вашем Диске, остальные ваши файлы ему недоступны. По вашему действию подписанный PDF загружается в папку на вашем Диске, а доступ к нему открывается так, как вы выбрали: всем, у кого есть ссылка, или конкретному человеку — письмо со ссылкой ему отправляет Google. Если вы отметили «Конвертировать в PDF» у документа, расширение загружает его на ваш Диск, Google переводит его в PDF, расширение получает этот PDF и сразу удаляет временную копию с Диска. Разработчику эти данные не передаются. Использование и передача информации, полученной через API Google, соответствуют Google API Services User Data Policy, включая требования Limited Use.
  • docs.google.com — только когда вы нажали «Отправить в Договор24» или «Подписать и отправить» в открытом документе Google: расширение получает у Google PDF именно этого документа, используя ваш вход в Google в этом браузере (без OAuth и без доступа к другим файлам). Google отдаёт файл через свой адрес googleusercontent.com.
  • new.dogovor24.kz — только если вы вошли в Договор24 в этом браузере, и по вашему нажатию: загрузка выбранного документа в ваше пространство, список ваших папок и ваша собственная подпись документа. Запросы идут от вашего имени с токеном вашей сессии; токен никуда больше не передаётся. Если вы включили уведомления о новых документах — ещё и раз в минуту проверка счётчика и списка ваших «Моих входящих» (название, отправитель, срок); документы при этом не скачиваются.
  • установленный у вас NCALayer (локальный адрес 127.0.0.1:13579), если он есть: расширение передаёт ему ваш же запрос на подпись, когда подписывать должно не оно — например, вы нажали «Отмена» в окне расширения или ещё не добавили ни одного ключа. Это соединение не покидает ваш компьютер, и делается оно ровно с теми данными, которые сайт и так отправил бы NCALayer напрямую.

Никакой аналитики, трекинга или загрузки удалённого кода расширение не использует.

5. Запрашиваемые разрешения

  • storage — локальное хранение зашифрованных ключей, настроек и журнала.
  • alarms — таймер автоблокировки: блокирует хранилище ключей после выбранного вами времени простоя; если включены уведомления о новых документах — проверка входящих Договор24 раз в минуту.
  • unlimitedStorage — защита локального хранилища от автоматической очистки браузером при нехватке места на диске (чтобы ваши ключи не пропали).
  • sidePanel — показ стартового экрана расширения в боковой панели браузера: она не закрывается при переходе в проводник, поэтому туда можно перетащить файл. Данные не передаются.
  • cookies — чтение только cookie сессии Договор24 (access_token, workspace_id): чтобы понимать, вошли ли вы в Договор24, и отправлять документы от вашего имени. Другие cookie расширение не читает.
  • notifications (необязательное) — Chrome спрашивает его, только когда вы включаете уведомления о новых документах в Настройках; без него расширение уведомлений не показывает.
  • identity (необязательное) — Chrome спрашивает его, только когда вы нажимаете «Подключить Google Диск» в Настройках: оно нужно для входа в Google в окне Google и сохранения подписанных PDF на ваш Диск.
  • доступ к сайтам — внедрение скрипта, заменяющего NCALayer. Скрипт подключается на всех сайтах, потому что NCALayer используют сотни порталов РК (egov.kz, КГД, goszakup, ЭСФ, stat.gov.kz, enbek.kz, imei.kz, new.dogovor24.kz и др.), а их список постоянно меняется. Скрипт не читает и не изменяет содержимое страниц: он перехватывает только обращение страницы к адресу NCALayer (127.0.0.1:13579) и бездействует, пока подпись не запрошена. После ответа расширения он в течение минуты отмечает ошибки на странице и отказы её сервера — только для журнала ошибок на вашем компьютере. По этому же адресу он может обратиться сам — чтобы передать запрос установленному NCALayer, когда подписывать должно не расширение (см. раздел 4). Отдельный небольшой скрипт работает только на страницах документов Google и только при активной сессии Договор24 показывает плашку с кнопками отправки; содержимое документа он не читает — PDF по вашему нажатию получает фоновая часть расширения у Google.
  • доступ к new.dogovor24.kz, docs.google.com и *.googleusercontent.com — отправка выбранных вами документов в Договор24 и получение PDF открытого документа Google (см. раздел 4).
  • доступ к tsp.pki.gov.kz — получение метки времени при подписании; обращения к ocsp.pki.gov.kz при подписи для ЕСЭДО и внутри PDF и к Google Диску покрываются доступом к сайтам, отдельного разрешения не требуют.

6. Удаление данных

Вы можете в любой момент:

  • удалить отдельные ключи и токены доступа в интерфейсе расширения;
  • выключить кнопки в Google Docs и уведомления о новых документах (Настройки → «Договор24 и Google Docs») или выйти из Договор24 на сайте — тогда расширение перестаёт обращаться к Договор24; при выключении уведомлений сохранённый список входящих стирается;
  • отключить Google Диск (Настройки → «Google Диск» → «Отключить»): токен отзывается у Google, адрес аккаунта забывается; полностью отозвать доступ можно на странице myaccount.google.com/permissions. Файлы на вашем Диске остаются вашими — удалить их можно в самом Google Диске;
  • стереть все данные кнопкой «Забыли пароль? Сбросить расширение» на экране блокировки;
  • очистить журнал ошибок («Обратная связь» → «Очистить журнал ошибок»);
  • отозвать доступ сайта к ФИО и ИИН: Настройки → «Кому видны ФИО и ИИН» → «Отозвать»;
  • удалить своё обращение к разработчику — написать на ilya.i.tarasov@gmail.com;
  • удалить расширение из браузера (chrome://extensions) — локальное хранилище очищается вместе с ним.
